# lab-plot

GUI для графиков измерений и интерактивного Steel REPL.

```powershell
cargo run --release
lab-plot.exe --preload-script scripts/arduino-start.scm
lab-plot.exe --preload-script scripts/base.scm --preload-script scripts/experiment.scm
cargo run --release -- --preload-script scripts/arduino-start.scm
```

`--preload-script <путь>` необязателен и может повторяться. Относительные пути
разрешаются от рабочего каталога процесса; пути с пробелами заключайте в кавычки.
`base.scm` и `experiment.scm` в примере — ваши файлы, перечисленные в нужном порядке.

Файлы читаются и выполняются однократно по порядку в существующем рабочем потоке
Steel, после регистрации функций приложения и до ручных команд REPL. Выполняются
все выражения верхнего уровня, включая обращения к серверу. Функции и переменные
остаются доступны в том же REPL; относительные `require` разрешаются от файла.
GUI продолжает работать во время исполнения, ручной Run доступен после завершения.

При автозагрузке открывается окно REPL с результатами и именами файлов. Ошибка
чтения, синтаксиса или выполнения останавливает оставшиеся стартовые файлы и
показывается в REPL (окно вновь открывается, если было закрыто). GUI и ручной REPL
остаются доступны; уже выполненные действия и определения не откатываются.
Кнопки Open, Save, Run и ручное исполнение сохраняют прежнее поведение.

Без аргументов запуск прежний. Файлы из `scripts` автоматически не подбираются;
список не сохраняется, отслеживания изменений нет.

Проверки без физического оборудования:

```powershell
cargo fmt --check
cargo check --all-targets
cargo clippy --all-targets -- -D warnings
$env:RUST_TEST_THREADS = '2'
cargo test
cargo test --release
```

Ограничение параллелизма тестов предотвращает таймауты при одновременной
инициализации множества Steel Engine в Debug. Проверки GUI используют кадры egui
без открытия нативного окна; один существующий WS smoke-тест требует отдельно
запущенного сервера и по умолчанию пропускается.
